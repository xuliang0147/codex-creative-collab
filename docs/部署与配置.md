# 部署与配置

## 先验证，不覆盖生产

本仓库来自已有本地系统的脱敏副本。首次使用先按 README 运行测试和隔离演示。不要把现有数据库复制进 Git，也不要在运行中的生产目录直接执行演示或迁移。

程序不会替你创建真实 Codex 任务。先在目标项目中分别创建可见任务，并以“产品 / 编导 / 剪辑 / 拍摄 / 平面 / 即梦”明确命名；获得真实任务 ID 和主机 ID 后再注册。不能用示例 ID 冒充绑定完成。

## 核心配置

| 变量 | 作用 |
| --- | --- |
| `CREATIVE_COLLAB_DB_PATH` | 账本 SQLite 完整路径 |
| `CREATIVE_COLLAB_ROOT` | 项目和素材根目录 |
| `CREATIVE_COLLAB_REQUESTER_LABEL` | 面向用户的称呼，默认“任务发起人” |
| `CREATIVE_COLLAB_FFPROBE` | 可选 ffprobe 可执行文件路径 |
| `CODEX_THREAD_ID` | 当前任务身份，由宿主提供；恢复操作会校验，不应冒用 |
| `CREATIVE_COLLAB_DISPATCH_QUEUE` | 可选派发队列目录 |
| `CREATIVE_COLLAB_FEISHU_RELAY_CONFIG` | 可选飞书编导中继配置路径 |
| `CREATIVE_COLLAB_FEISHU_CHAT_ID` | 飞书目标群，必须自行明确设置，不内置收件人 |
| `CREATIVE_COLLAB_FEISHU_DOC_QUEUE` | 文档队列目录 |

先用一个新目录配置：

```bash
export CREATIVE_COLLAB_ROOT="$HOME/codex-creative-workspace"
export CREATIVE_COLLAB_DB_PATH="$CREATIVE_COLLAB_ROOT/00_协作账本/registry.sqlite"
python3 -m creative_collab.cli bootstrap
python3 -m creative_collab.cli agent-list
```

MCP 启动命令为 `python3 -m creative_collab.mcp_server`；将工作目录设置为仓库根目录，并给 MCP 进程传入上述相同环境变量。它使用 stdio，不提供公网 HTTP 服务。

## 注册团队

1. 在新的编导任务中运行 `python3 -m creative_collab.cli register-current --role 编导 --host-id local`，其中主机值必须与实际运行位置一致。默认追加；不要使用 `--replace` 覆盖已有编导。
2. 通过 `call-tool director_team_register` 注册四个专属执行任务，参数结构见 `examples/director-team.example.json`。先将所有 `YOUR_...` 替换为已核验的实际值。
3. 用 `call-tool director_team_list '{}'` 回读团队；项目创建后用 `project_route_get` 核对各角色目标与所属编导。
4. 第二个产品使用另一组真实任务，不共用已有执行任务。

```bash
python3 -m creative_collab.cli call-tool director_team_register \
  "$(cat /path/to/private/director-team.local.json)"
python3 -m creative_collab.cli call-tool director_team_list '{}'
```

注册第一组团队会使旧的全局执行绑定失效，保留已有历史；旧的未发送派发会失效并要求重新准备。因此，在现有生产账本上执行前需备份并明确批准，不能把注册当成无副作用的查询。

## 派发

优先使用 Codex 宿主已有的真实任务消息能力，严格执行 `dispatch_prepare -> 实际发送 -> dispatch_mark_sent -> 真实目标回复 -> dispatch_mark_received`。只有接收角色接受工作单后才算开始执行。

CLI 另有 `send-dispatch`，通过本机 Codex CLI `exec resume` 启动既有任务。需要提供可用的 `--codex-binary`；默认历史路径为 `/Applications/ChatGPT.app/Contents/Resources/codex`，不保证适合所有安装位置。它不是跨主机远程控制实现，不能仅凭 `host_id` 就启动另一台电脑的任务。不要与同一任务的现有运行实例并发使用。

## 飞书接入（可选）

已有桥接仓库负责接收消息，本仓库只提供协作和输出侧组件。飞书配置、账号登录态都保留在仓库外。

- `creative-collab-team-runner.py`：团队账本、队列入口，与个人默认目录分离。
- `creative-dispatch-worker.mjs`：消费派发队列；当前入口使用 `/usr/bin/python3` 和历史 Codex 默认路径，部署时须核实其兼容性；优先使用已验证的宿主原生消息路由。
- `creative-feishu-doc-publisher.py`：项目文档请求入队。
- `creative-feishu-doc-publisher-worker.mjs`：消费项目同步与评论拉取请求，使用 `/usr/local/bin/lark-cli`，具体授权身份由本机受控 profile 提供。
- `creative_collab.feishu_relay_worker`：恢复指定编导并将最终回复发回配置群，不应将同一个中继配置跨团队复用。

中继字段见 `examples/feishu-relay.example.json`，只填写路由与本地配置位置，不在里面放 Token、Secret。示例 JSON 不可直接作为生产配置。

`deploy/feishu_creative_team/*.example.plist` 是 macOS 启动模板，保留 `RunAtLoad/KeepAlive` 语义但不会自动安装。必须先替换所有占位路径、群号，核对 Node/Python/Codex 路径，创建运行目录，并以前台测试验证后，才能自行安装。默认不绑定任何代理；代理如有需要单独按实际环境配置。

文档服务完成创建/更新后，须回读文档 URL、项目绑定和正文；队列结果为 complete 不等于用户已审核视频。飞书授权失败时保留产物并报阻塞，不能捏造发送成功。
