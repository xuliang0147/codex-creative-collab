# 安全与限制

## 数据分层

- GitHub：源代码、测试、空配置示例、通用模板、中文文档。
- 本地私有运行目录：SQLite、真实任务绑定、队列、项目状态、素材、成片与日志。
- 系统钥匙串或工具私有配置：飞书、Codex 等账号授权，不纳入仓库。

本仓库没有携带生产数据库，也没有从历史中删除数据。恢复代码不等于恢复素材、账号或业务历史。

## 部署边界

当前实现面向本人可信本机，不是多租户安全服务。角色与当前任务 ID 的检查防止工作流误路由，不能防御本机已具备文件/进程权限的恶意用户。CLI 的通用 call-tool 和本机数据库也应仅向可信执行环境开放。

两个团队不应同时控制同一编辑器窗口。工程目录隔离和任务名称区分不能代替 UI 操作互斥。遇到目标窗口不明确、未保存工程或进程异常时停止操作，先确认现场。

中继配置适用于指定编导和群。不要给多个团队共用同一个 Feishu relay 配置，也不要把 `host_id` 当成独立身份认证凭据。跨主机派发需要宿主提供真实的远程消息能力。

`sync-project` 会更新已绑定的同一云文档，发布服务可能创建文档、授权群成员访问。只有核对目标群与授权后才启动 worker。它不是无副作用的只读操作。

## 已知兼容性

- 当前整理验证使用 macOS、Python 3.12、Node.js 24、ffmpeg/ffprobe。含 fcntl 和本机进程管理，不能据此宣称 Windows 原生兼容。
- 原始代码在 Python 3.13 测试时出现 SQLite 连接回收的 ResourceWarning，测试仍通过；本次未改动这项历史实现，未声称全版本无警告。
- 旧派发 worker 尚未支持即梦作为发送角色；使用真实宿主消息派发时遵守完整回执流程。
- 默认 Codex CLI 路径是历史安装位置，新的安装需要显式核对，不自动扫描账号目录或替换宿主。
- 不具备自动判断商业素材授权、医疗功效、账号合规或用户最终审片结果的能力。

## 后续上传

此仓库是整理后的独立副本，不是对本地整个工作目录的镜像，不会自动同步后续修改。再次更新时只纳入相关源码与测试，检查个人路径、真实收件人、凭据和素材，运行测试再推送。不要对原始混合工作目录执行整体上传。
